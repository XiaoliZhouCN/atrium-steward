> **版本**：v1.0
> **范围**：`D:\Repositories\` 全域（跨仓库）
> **维护者**：AtriumSteward
> **上位依据**：[`WORKSPACE_SPECIFICATION.md`](WORKSPACE_SPECIFICATION.md) §6（本文是其 §6.1 的展开，不改变任何权限结论）
> **与本仓库的关系**：AtriumSteward 常驻的三位管家见 [`AGENTS_ROLES.md`](AGENTS_ROLES.md)；本文只定义**档位**与**映射规则**，不定义人格。

---

## 0. 两张表，一件事

Agent 的权限和它的"人格"是两件不同的事，必须分开：

| 概念 | 是什么 | 一句话判据 | 权威 |
| :-- | :-- | :-- | :-- |
| **档位** | 权限与作用域 | "能写哪里、能不能提交" | 本文 |
| **管家** | 人格与服务域 | "谁在服务你、管哪一块" | 各仓库角色文档 |

**核心规则：一个管家可以同时持多个档位。** 管家是"人"，档位是"职务"——同一个人做架构设计时戴建设档，写脚本时戴视务档。不存在"一个管家只对应一张牌"的绑定关系。

## 1. 档位表

| 档位 | 作用域 | 权限 | 典型动作 | 规范原名 |
| :-- | :-- | :-- | :-- | :-- |
| **建设档** | 设计、契约、结构 | 可建分支、提交、推送；**不可开 PR** | 目录规划、接口骨架、架构文档、必要函数框架、契约字段提案 | 架构师 Agent |
| **掌籍档** | 记录、验证、归档 | 仅可修改本地文件 | 测试补充、验证执行、文档同步、索引维护、内容整理与分流 | 测试 + 文档管理 Agent |
| **视务档** | 实现、呈现 | 仅可修改本地文件 | 具体模块功能实现、工具与脚本、视觉与交互呈现 | 模块开发 Agent |

- 「规范原名」列仅用于对照 `WORKSPACE_SPECIFICATION.md` §6.1，**不是第二套可用的权限定义**；引用时只引用档位名。
- 档位名不暗示工作内容属于代码域：掌籍档同时覆盖"补测试"与"整理手账"，两者权限完全相同。

### 1.1 叠加与降级（硬规则）

1. **可叠加**：同一任务里跨档位时，逐动作判断该动作需要哪个档位，不按"当前身份"整体授权。
2. **取最小**：一次连续工作按涉及动作的**最低**档位执行；需要提权时单独提出，不做整段提权。
3. **禁止发明**：不得创造第四档位或自定权限。发现缺档位时登记为待决项（见 §4）。
4. **授权三要素**：声明档位时必须同时说明 **作用域 + 权限 + 不可做的事**，只写名字不算授权。
5. **不可逆动作**：删文件、改目录边界、装依赖、建仓库、开 PR，无论持哪一档，都必须先取得人工确认。

---

## 2. 映射规则

1. 每个管家必须至少持一个档位；档位由其**具体动作**决定，不由其人格决定。
2. 管家名**不得**作为权限依据出现在任何规范、脚本或配置里——只有档位名可以。
3. 新增管家时，若其全部动作都能落在现有三档内，**不构成新档位**，无需改本文。

## 4. 子仓库 `AGENTS.md` 的扩写规则

`AtriumSteward/AGENTS.md` 是**权威基础**。其他仓库的根级 `AGENTS.md` 处理其与本文及 `AGENTS.md` 的关系时：

| 情形 | 允许 | 要求 |
| :-- | :-- | :-- |
| **扩写** | ✓ | 提交本仓库特有的边界、禁令与最小验证项；不得复制上级条文，只做链接引用 |
| **收紧** | ✓ | 可以设定比上级更严格的约束（如"本仓库不允许建分支"），需在条目内说明理由 |
| **覆盖 / 冲突** | **条件允许** | 必须在条目开头标注 `[MARK]`，并写明：覆盖了哪一条、为什么必须覆盖、影响范围 |
| **静默改写** | ✗ | 与上级不一致却不标注，视为违规；发现即回写为链接引用或补标 `[MARK]` |

`[MARK]` 条目的格式：

```text
- [MARK] <本仓库约束>
  - 覆盖：<被覆盖的上级条目，含文件与章节号>
  - 理由：<为什么本仓库必须不同>
  - 影响：<仅本仓库 / 涉及跨仓库协作>
```
